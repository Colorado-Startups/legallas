## 2. Formation requirements

### What makes a great formation record

No outside standard defines this. The closest public yardsticks are what diligence asks for (S46) and what formation services hand a founder (S47, S48). From those and the deadlines below, a stated-reason test with five parts:

1. **Present.** Each document that applies exists, and each one that doesn't apply says why.
2. **Signed.** By the right people, with the filed copy for anything filed.
3. **In order.** Filing, then incorporator action, then board consent, then stock purchase and payment, then 83(b) within its window. IP assignments no later than the stock they're tied to.
4. **Reconciled.** Ledger equals cap table equals the signed purchase agreements.
5. **Located.** The founder can see where each one lives.

Legal requirement and market habit should stay separate on the page. Bylaws, a filing, a registered agent and state reports are legal duties. An LLC operating agreement isn't (S30). An 83(b) election is optional but has a hard clock (S1). Founder IP assignments and vesting are what investors expect, and the law only sets how a transfer must be done (S41, S42).

### Invented samples used in the tests

- **Sample A:** a Delaware C corporation run from Colorado. Two founders. 10,000,000 authorized shares, par $0.0001, 8,000,000 issued. Founder shares transferred Friday 2027-01-15. Gross assets $50,000.
- **Sample B:** a Colorado corporation, no other state.
- **Sample C:** a Colorado LLC with two members, periodic report month June.

## 4. Standards

### The two sample-size answers

**A goal of at least 90%.** Pass rule: the 95% Wilson lower bound (S71) must reach 90%. The Wilson lower bound with no failures is n / (n + z squared), so n / (n + 3.84) >= 0.90 gives n >= 9 x 3.84 = 34.6.

| Sample | Failures allowed | Observed | Wilson low | Chance of passing if the true rate is 90% / 95% / 97% |
|---|---|---|---|---|
| **35 (floor)** | 0 | 100% | 90.1% | 2.5% / 16.6% / 34.4% |
| 100 | 4 | 96.0% | 90.2% | 2.4% / 43.6% / 81.8% |
| 150 | 7 | 95.3% | 90.7% | 1.4% / 52.3% / 91.7% |
| **200 (recommended)** | 11 | 94.5% | 90.4% | 1.7% / 70.0% / 98.2% |
| 300 | 19 | 93.7% | 90.3% | 1.7% / 88.1% / 99.9% |

- **Floor: 35 distinct items.** Exact binomial agrees: ln 0.05 / ln 0.9 = 28.4, so 29 one-sided; ln 0.025 / ln 0.9 = 35.01, so 36 two-sided. But it's brittle. A system truly at 95% clears it only 16.6% of the time (0.95^35).
- **Recommended: 200 distinct items, at most 11 failures.** It sits beside the published legal benchmarks: Magesh used 202 queries (S62), Vals 210 (S65). The NIST formula (S72) for telling a true 95% from a floor of 90%, one-sided at 5%, gives N = ((1.645 x 0.300 + z x 0.218) / 0.05)^2: 183 at 80% power, 239 at 90% power, or 203 and 259 with its continuity correction. So 200 is about 80% power.
- **For small n,** Brown, Cai and DasGupta favor Wilson or Jeffreys at n of 40 or less (S73, search excerpt only). NIST recommends an exact method when failures or n are very small (S71).
- **Count distinct questions, not runs.** Repeating one question isn't a new trial.

**A goal of zero leaks.** Any single leak fails the gate outright. The sample only sets what a clean run rules out. With no events in n independent trials, (1 - p)^n = 0.05, so p is about 3/n (S74, the rule of three, S75, S76).

| Distinct trials, no leaks | 95% upper bound, exact | 3/n |
|---|---|---|
| 22 | 12.7% | 13.6% |
| 59 | 5.0% | 5.1% |
| 100 | 3.0% | 3.0% |
| **299** | **1.0%** | 1.0% |
| 2,995 | 0.1% | 0.1% |

**Defensible minimum: 300 distinct cross-boundary attempts,** which supports "95% confident the leak rate is under 1%." It catches a true 1% leak rate 95% of the time (1 - 0.99^300) but a true 0.1% rate only 26%. So say what the number shows; a clean run doesn't prove none.

**Use statistics only where behaviour is random.** Access control in code is deterministic: test every route against every role, and report coverage, not a rate. The rule of three is for the model-mediated paths, such as prompt injection.

### What this means for the repo's eval today

- `web/scripts/ask-eval-report.ts` computes Wilson intervals, but `atLeast` passed on the **point estimate** (`r.rate >= goal`), so 9 of 10 met ">= 90%", though its Wilson low is about 60%. Since #199, a share target is met only from its minimum sample (35 for 90%), and the report shows n, the minimum and the Wilson bound beside each target.
- `.github/workflows/replica-eval.yml` says a default run is 22 items. Even if every item is an independent chance to leak, zero failures rules out only rates above 12.7%.
- The ">= 98%" quote targets need n/(n + 3.84) >= 0.98, so **189 clean units** for a Wilson low of 98% (exact one-sided: 149). The ">= 85%" target needs 22 clean items. "100%" targets are zero-failure goals, read with the table above.
